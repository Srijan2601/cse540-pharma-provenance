# docs/

Design record, document formats, test plan and analysis data. **This repo is public:** no ASU IDs, emails, private keys, or the proposal/team-contract PDF (it contains student IDs).

## Contents

| Path | What |
|---|---|
| [`design-decisions.md`](design-decisions.md) | The design gaps the proposal left open (C1–C7, O1–O6, D1–D6), the draft's answer to each, and what the code does |
| [`schemas/`](schemas/) | JSON Schemas and **synthetic** examples for the IPFS documents: lot metadata, regulator certificate, sensor log (**O2**) |
| [`testing/`](testing/README.md) | The test plan as implemented: the test layers, the command for each, the counts, and what is not tested automatically (**D4**) |
| [`analysis/data/`](analysis/data/) | The gas report, generated by `npm run gas:report`: [`gas-report.md`](analysis/data/gas-report.md) and `gas-report.json` (**D5**) |
| [`meetings/TEMPLATE.md`](meetings/TEMPLATE.md) | Template for sync notes: decisions and action items only. No notes are committed. |

The final report and the demo video are not kept in this repository.

## Analysis topics (proposal §2, §6)

The analysis itself is written in the report. This table names the method and the source of each topic's data.

| Topic | Method | Data source |
|---|---|---|
| Gas cost | Gas per function and per lot lifecycle, measured from transaction receipts on Hardhat's in-process network. `GAS_PRICE_GWEI` adds a cost column in POL, and `POL_USD` with it one in US dollars. | `npm run gas:report` in the repository root writes `analysis/data/gas-report.json` and `analysis/data/gas-report.md`. `npm test` fails when they no longer match the contract. |
| Scalability | Storage growth per lot (latest-only storage + events), event-query limits on public RPCs | Contract design + measurements |
| Privacy | What is public on-chain vs on IPFS vs encrypted vs never uploaded (**O5**) | Data classification table |
| Regulation | Fit with U.S. DSCSA electronic tracing requirements and FDA exemptions (proposal ref. [2]) | Literature |
| Centralized comparison | Qualitative criteria table: shared DB vs Fabric vs public chain (trust, auditability, cost, patient access) | Literature + the gas report |
| Trusted keys | What the regulator key and the oracle key can and cannot do (see `contracts/README.md`) | Contract roles |
