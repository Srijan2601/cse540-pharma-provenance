## Analysis topics (proposal §2, §6)

The analysis itself is written in the report. This table names the method and the source of each topic's data.

| Topic | Method | Data source |
|---|---|---|
| Gas cost | Gas per function and per lot lifecycle, measured from transaction receipts on Hardhat's in-process network. `GAS_PRICE_GWEI` adds a cost column in POL, and `POL_USD` with it one in US dollars. | `npm run gas:report` in the repository root writes `analysis/data/gas-report.json` and `analysis/data/gas-report.md`. `npm test` fails when they no longer match the contract. The Amoy receipts of 2026-11-26, compared call by call in [`amoy-deployment.md`](amoy-deployment.md#gas-on-amoy-compared-with-the-hardhat-network). |
| Scalability | Storage growth per lot (latest-only storage + events), event-query limits on public RPCs | Contract design + measurements ([`amoy-deployment.md`](amoy-deployment.md#rpc-endpoint): event-query limits of two public Amoy endpoints) |
| Privacy | What is public on-chain vs on IPFS vs encrypted vs never uploaded (**O5**) | Data classification table |
| Regulation | Fit with U.S. DSCSA electronic tracing requirements and FDA exemptions (proposal ref. [2]) | Literature |
| Centralized comparison | Qualitative criteria table: shared DB vs Fabric vs public chain (trust, auditability, cost, patient access) | Literature + the gas report |
| Trusted keys | What the regulator key and the oracle key can and cannot do (see `contracts/README.md`) | Contract roles |
